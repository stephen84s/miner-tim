# PROC-06 — Mutation testing, because the break-testing rule never bound the author.

**Status:** Completed

The rule existed and was good — but lived in `_shared-context.md`, headed *"for MinerTim reviewers"*. So reviewers break-tested and caught the author **eight times**, several occasions recorded here as "break-tested" when the claim was false. The subtler half: hand break-testing means *choosing* a mutation, and one the test catches for an unrelated reason proves nothing — an all-zeros pin *rejects* everything; a dropped test socket makes the miner reconnect on EOF. Fixed three ways: the obligation moves into `CLAUDE.md`'s protocol with those examples; `scripts/mutants.sh` prefers the tool, which tries every mutation; and an **advisory** CI job. Cost measured, and scope is everything — **28 min unscoped for 8 mutants, ~31-33 s scoped for 20**. First real run found a survivor in this session's own `hex_decode`, which is an **equivalent mutant** (`|` vs `^` agree on all 256 nibble pairs) — the reason the job must stay advisory. Not established: the crate generates **3,196** mutants (`vm.rs` 855, `jit/aarch64.rs` 710) and almost none have been run. `pool_connection.rs` is **88** on `main` and 95 on the in-flight branch — an earlier note gave 95 without saying which tree. **Round 2 returned NOT MERGEABLE, two majors.** The silent-green fix was one step short in exactly the way this PR exists to prevent: the count filtered with `-F` alone while the run also applies `-E`, so the exclusion could empty the set and the script would announce one mutant, test none and exit 0 — round 1's own finding surviving inside its fix. And the merge that brought `main` in broke the GFM task board with three blank lines, dropping PROC-06 itself out of the rendered table, while the entry justifying the merge called the append clean. Both fixed and re-verified against GitHub's renderer; five minors closed, and R2-F7 settled from live check-run data — a failed `continue-on-error` job does report `conclusion=failure`, so the advisory gate is visibly red without blocking. **Round 3: MERGEABLE, no blockers, no majors** — it executed every exit path rather than reading them and could not make the script report success having tested nothing, bar one case it found: a scope whose mutants are *all unviable* exited 0, the same silent-green shape one layer further out. Now exit 66. Its other minors closed too: this script's exit codes were colliding with cargo-mutants' own (a mutant surviving *by hanging* exited with the code meaning "your filter matched nothing"), so they moved to 64/65/66; an orphaned duplicate comment block; `cargo-mutants` pinned to 27.1.0 since the script parses `--list`; and the stale "21 mutants / 33 s" swept to 20 / ~31-33 s.
