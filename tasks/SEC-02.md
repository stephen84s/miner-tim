# SEC-02 — TLS pool connections authenticated by default (#20).

**Status:** Completed

`NoVerifier` accepted every certificate — TLS encrypted but authenticated nothing. Investigation changed the fix three times over: **XMRig does not verify either** (`fingerprint == nullptr || match` is the whole check), so parity was no argument; the issue's premise was wrong — surveying five pools, expired certs are **1 case in 5**, while the dominant pattern is **self-signed certs with placeholder hostnames** (`CN=mining.pool`, stock daemon cert, valid to 2126), which rules out an expiry-only exception; and **`webpki-roots` was already a dependency that had never been used**. Default is now full WebPKI validation — chain, hostname, expiry. Opt-in is SHA-256 pinning (`--tls-fingerprint`, XMRig-compatible), chosen over an insecure-mode toggle because a pin **authenticates**: a substituted cert fails, which a bypass cannot detect. Second defect found while reading: `NoVerifier` also stubbed the TLS 1.2/1.3 **signature** checks, so there was no proof the peer held the private key; the pinning verifier delegates those to real WebPKI. Fails loud by design — unbuildable verifier panics, malformed pin exits 2. 167 tests (149 lib + 18 bin), clippy clean. **`src/hex.rs` had zero tests**; writing its first ones immediately failed, exposing a **second, pre-existing** defect — `u8::from_str_radix` accepts a leading sign, so `hex_decode("+1")` returned `Some([1])`, decoding non-hex. Reachable from pool-supplied `blob`/`target`/`seed_hash` for the project's life. Rewritten to decode nibble-wise, fixing that and the panic together. **Round 1 returned NOT MERGEABLE, five majors, all fixed** — and review exercised the TLS path in **real handshakes** against a local `openssl s_server`, which this entry had listed as unverified. Worst finding: a pin could be **silently inert** — TLS is inferred from the port, and `gulf.moneroocean.stream:20128` is not in `TLS_PORTS` despite speaking TLS, so the log announced a pin two lines before `Connected to pool (plain TCP)`. Now refused. Also: an env pin was silently erased by an empty `--tls-fingerprint` (**R10-F2 recurring in the file that documents it**, with the claim of parity disproved against the binary); the README printed **monerohash's** fingerprint under supportxmr; the shipped quick-start pool is self-signed and this change breaks it, undisclosed; and **the default verifier had no test coverage** — swapping it for accept-anything left the suite green. Break-tested twice, the first mutation being wrong in a way that would have closed the finding falsely. **Round 2 also NOT MERGEABLE, four majors.** Round 1's major #5 was only **half-closed** and the entry claimed otherwise: the test held a *helper* while the mutation targeted the wiring, so the defect was still shippable green. It took **three attempts** — testing the helper failed, collapsing to one call site failed (the mutation replaces the argument there), and only a **real in-memory TLS handshake** closed it, since nothing can inspect a built `ClientConfig`. That also gave the change its first reproducible evidence that pinning *accepts* a self-signed cert. Also: the refusal guard sat behind `TcpStream::connect`, so its test needed a live connection to a host with a blackholing A record — 75 s, and a **failure** rather than a skip with no route; `parse_tls_fingerprint_with` had no tests despite being split out *for testability*; and the PR body was never updated, the **third round 2 in this repo** to find that. **Verified live 2026-09-16**, closing the gap every revision had to declare open: 6 hours against `monerohash.com:9999` (TLS port, genuinely expired cert) tested **both halves**. Negative — the default rejected the real expired certificate with a precise error; `NoVerifier` accepted it silently for the project's life. Positive — the same certificate pinned gave **354 accepted / 0 rejected / 0 withheld / 0 errors**, **10 TLS handshakes across 9 donation rotations, 0 handshake failures, 0 plain-TCP fallbacks**, median 2267.4 H/s. Note LIVE-01 used port **2222 — plain TCP** — so it exercised none of this code. Log: `LIVE6H_TLS_RUN.log`. Still untested: a pin breaking on renewal (the cert never changed), the self-signed case against a real endpoint, and 12-thread behaviour.
